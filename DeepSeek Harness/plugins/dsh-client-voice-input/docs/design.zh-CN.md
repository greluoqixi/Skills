# 离线语音输入设计

## 目标与边界

语音只用于生成用户输入草稿；用户自行检查并发送。当前版本只处理一次最长 80 秒的录音，停录后开始识别。不依赖 Linux 启动器、固定端口、GPU、云端语音 API 或开发者机器目录。首次下载模型与安装 Python 包需要网络；后续转写无需网络。

## 组件

| 部分 | 责任 |
| --- | --- |
| `lib/client.js` | Harness `conversation.input.activity` 插槽与设置中心分区、双语界面、浏览器录音、16 kHz PCM 转换、草稿插入。 |
| `lib/index.js` | 宿主认证 API、状态缓存、安装编排、按需启动并停止识别子进程。 |
| `lib/core.js` | 引擎注册表、XDG/`DSH_VOICE_HOME` 路径、`~` 展开、配置与 WAV 校验。 |
| `lib/store.js` | 配置读取与原子写入，损坏文件回落默认值。 |
| `lib/runner.js` | 子进程执行（超时、取消、进程组）与限长请求体读取。 |
| `runtime/setup.py` | 创建独立虚拟环境，验证 Python 包，从官方发布页按需下载并安全提取模型。 |
| `runtime/transcribe.py` | 一次调用读取一次 WAV，CPU 离线识别后输出一行 JSON，进程退出。 |

## 状态与数据流

`未配置 → 配置中 → 就绪 → 录音中 → 转写中 → 空闲`。转写成功即把文字写入草稿并回到空闲，不额外显示状态；任一步出错会回到可操作的配置或空闲状态，并说明原因。安装失败可再次点击安装；已下载的模型与已安装的包会复用。

输入框里始终只有一个控件：`conversation.input.activity` 里的麦克风。该插槽只在录音或转写期间展开，配置和报错都不会挤动模型选择器、发送键或工具栏布局。未就绪时点击麦克风打开设置卡片；就绪后同一次点击直接录音。就绪状态直接体现在麦克风上的状态灯：可用为绿色，仍需配置为红色，检测中为琥珀色呼吸；状态不占输入框宽度，也不再以文字贴在图标附近。浮层只留给需要阅读的内容：麦克风权限失败、未识别到语音、识别期间草稿被改动。设置卡的状态行使用同一颗状态灯，配一行说明和一个显式的「重新检查」按钮，检测期间按钮转圈。状态旁的「!」按实时状态生成：检测中、未知、已就绪，或明确列出还缺哪一项；模型目录与 Python 两行也各自标注「已就绪 / 未安装」，随每次检查更新。

鼠标悬停或键盘聚焦会弹出深色提示卡：左侧「听写」，中间同一颗状态灯加状态文字，右侧是一个带底色的快捷键文字（键名之间用加号连接）。它替代原生 `title`，让状态与快捷键一眼可读，也跟随页面主题而不是操作系统。

键盘同样可以开始录音：客户端向 Harness 的快捷键服务注册 `voice-input.dictate`；冲突检测、键帽显示与偏好持久化都由该服务负责，插件卸载时一并注销。默认值覆盖六个运行时/平台组合——`Mod+Shift+D`；Linux Web 只允许 `Mod+Slash`、`Mod+Shift+Comma`、`Mod+Shift+Period`，因此该平台默认 `Mod+Shift+Comma`。「输入」卡片里的快捷键行是一个可点击的整体控件：一个底框里直接排文字，键名用加号连接（如 `Ctrl+Shift+D`），点击即进入录制，Esc 或点击别处取消；录制通过同一服务完成（先 `describeBinding`，再用审核过的 revision 调 `edit`），所以本插件设置与「设置 → 通用 → 快捷键」两处永远不会不一致；被拒绝的组合会说明原因并保持录制状态，方便再试。

设置保留两个入口：麦克风右键菜单（`onContextMenu`，同时覆盖触屏长按）与设置中心的 `settings.section` 页面。两处渲染同一个 `SettingsForm`，避免配置语义分叉。

配置卡片面向首次使用者：面板按「状态 → 主操作 → 当前生效路径 → 语言 → 高级 → 操作」分区；所有说明（总览、模型目录、Python 路径）统一为「!」悬停提示（键盘聚焦同样触发），面板里不再堆叠说明段落；「当前生效的配置」始终展示模型目录与 Python 可执行文件的绝对路径——托管默认值也会显示，未安装时标「未安装」——因此用户不必靠猜测确认插件用的是哪个目录。只有一套交互：路径框可直接编辑，右侧两个图标分别是复制与选择目录（`ctx.uiWorkspace.pickDirectory()`）。选择即生效；手输内容点「保存设置」生效。Python 选择虚拟环境目录后由宿主解析解释器，失败则把所选目录留在输入框里供修正。

1. 页面加载后，客户端查询 `GET /api/voice.status`。宿主检查模型文件，并实际用选定的 Python 导入 `sherpa_onnx`、`numpy`；仅当两者都成功才允许录音。
2. 用户点击安装时，客户端先保存空的手动路径，然后调用 `POST /api/voice.setup`。宿主启动安装子进程；虚拟环境与模型分别写入 XDG 数据目录。下载使用临时文件和受限提取，要求两个预期文件齐全。
3. 用户点击录音时，浏览器调用 `getUserMedia`，捕获当前草稿的插入选区与版本。录音期间输入框展开为通栏录音条：左侧圆形「×」丢弃本次录音（不转写），中间是动画波形与计时，右侧实心「■」结束并转写。键盘是同一状态机的快捷键：Esc 立即取消，Enter 结束录音并把结果写入草稿，「■」完全等价；两者都不会自动发送，用户保留修改与手动发送的空间。停录后将音频解码、下混并重采样，生成 16 kHz 单声道 16 位 WAV。
4. 客户端把 WAV 交给 `POST /api/voice.transcribe`。宿主验证格式及 3 MB 上限，启动一次 Python 进程。模型只在这次进程中加载；请求结束后进程退出，不常驻。
5. 客户端把返回文本通过 `InputActions.insertText(text, span)` 写入原草稿。草稿版本变更时该方法拒绝插入，界面保留文本并提供复制。

## API 与配置

| 路径 | 方法 | 作用 |
| --- | --- | --- |
| `/api/voice.status` | GET | 返回配置、生效路径（`modelDir`、`python`）、托管默认值、模型及运行时就绪状态。 |
| `/api/voice.config` | POST JSON | 保存 `modelDir`、`python`、`language`。前两者为空表示使用插件托管位置。 |
| `/api/voice.setup` | POST | 按需安装托管运行时和模型；重复执行可恢复不完整安装。 |
| `/api/voice.transcribe` | POST WAV | 返回 `{ "text": "..." }`，不保存音频。 |

路由由 Harness Connection 注册，沿用其所有者认证。配置位于 `$XDG_CONFIG_HOME/dsh-client-voice-input/config.json`；托管运行时和模型位于 `$XDG_DATA_HOME/dsh-client-voice-input`。未设置 XDG 变量时遵循用户主目录下的 XDG 惯例。**源码中没有用户机器绝对路径**；用户手动选定的路径只写入自己的配置文件。

## 生命周期和失败恢复

- 麦克风权限拒绝：显示浏览器权限错误，不启动推理。
- 模型缺失或 Python 导入失败：打开设置面板；可重新托管安装或指定已有文件。
- 网络中断：安装失败但不更改已有可用模型；下次点击安装重试。
- 草稿在识别期间变化：不覆盖新草稿，保留转写结果用于复制。
- 插件卸载、Harness 退出或转写请求取消：中止相关子进程。Linux 启动器关闭应用窗口时会退出 Harness，因而不会留下识别进程。

## 可移植性

源码中不出现任何机器相关路径：模型、虚拟环境、配置全部由 XDG 惯例推导，或用 `DSH_VOICE_HOME` 收拢到单一目录（测试与便携安装用）。用户填写的模型目录与 Python 路径允许 `~/` 前缀，保存前展开为绝对路径；除此之外不接受相对路径，避免宿主猜测工作目录。安装位置（profile 中的 `link:`）属于用户环境，不进入仓库。

环境变量：

| 变量 | 作用 |
| --- | --- |
| `DSH_VOICE_HOME` | 把数据、配置收拢到该目录（`data/` 与 `config.json`）。 |
| `DSH_VOICE_PYTHON` | 托管安装时使用的系统 Python（默认 `python3`）。 |

## 后续扩展

引擎是数据驱动的：`lib/core.js` 的 `ENGINES` 描述每个识别器的目录名、归档、来源、文件清单、语言与两个脚本（安装 / 转写）。新增识别器只需加一条描述与对应的两个 Python 脚本，宿主路由、设置界面与草稿写入都无需改动。保持 `{text}` 转写结果与草稿插入契约不变，还可以增加 VAD 自动分段、设备选择、热词或术语纠错、下载进度展示。实时逐字识别属于独立功能，应在当前“停录后转写”流程稳定后设计。

## 验证记录

在 DSH `0.2.1-rc.2` 上验证插件加载、输入框按钮、首次配置面板、托管环境及模型安装；用 sherpa-onnx 官方中文短音频经 Harness 认证 API 完成一次转写。`npm test` 覆盖配置验证、WAV 限制、模型文件判断及宿主路由；发布包清单检查排除了模型和 Python 缓存。
